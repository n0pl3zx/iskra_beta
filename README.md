# Искра (Iskra) — мессенджер для ПК

Тёмный настольный мессенджер в духе Telegram, написанный целиком на **Rust**
(GUI — `egui`/`eframe`, сеть — TCP + JSON). Работает и на одном компьютере,
и в локальной сети между несколькими ПК.

```
        ✦
      ИСКРА
быстрый мессенджер
```

> **English.** Iskra is a small desktop messenger written in Rust. It has a
> built-in TCP/JSON server, real-time chats, four themes and four interface
> languages (RU / EN / DE / ES). It works out of the box on a local network;
> see **Удалённая работа** below for remote connections. Windows-only for now.

---

## Что умеет

- Четыре темы оформления (Графит, Светлая, Изумруд, Индиго), масштаб интерфейса
  90–125 % и переключатель анимаций — всё в **Настройках** (шестерёнка внизу слева
  или справа вверху на экране входа). Выбор запоминается.
- Четыре языка интерфейса: **Русский, English, Deutsch, Español**. Переключаются
  там же, в настройках, и запоминаются. На всех языках, кроме русского,
  приложение называется **Iskra**; ответы сервера тоже переводятся.
- Плавные анимации в духе macOS: цвета тем перетекают друг в друга, панели
  настроек, профиля и эмодзи мягко проявляются, строки чатов выезжают каскадом,
  кнопки и переключатели пружинят при наведении.
- Знакомая «искра» вместо логотипа и цветные эмодзи в панели ввода
  (48 штук, ровная сетка 8×6, вставка по клику).
- Регистрация и вход по логину и паролю (пароли хранятся в виде соли + SHA-256, 4096 итераций).
- Список чатов с аватарками, последним сообщением, временем, счётчиком непрочитанных.
- Переписка в реальном времени: сообщения приходят мгновенно, без перезагрузок.
- Индикатор «печатает…», статусы «в сети» / «был(а) …», галочки прочтения.
- Разделители дат («Сегодня», «Вчера», «17 ноября»), история переписки на сервере.
- Поиск по контактам, эмодзи-панель, копирование сообщения по правой кнопке.
- Встроенный сервер: приложение само поднимает сервер на порту **8787**.
- Автопереподключение при обрыве связи.
- История и аккаунты хранятся на сервере, клиент при входе подтягивает всё заново.

## Быстрый старт

Готовый `Iskra.exe` лежит в разделе **Releases** (в репозиторий бинарник не входит).
Положите его рядом с `Искра.bat` и запустите.

1. Запустите **`Искра.bat`** (или `Iskra.exe`).
2. В окне входа переключитесь на **«Нет аккаунта? Переключить»**.
3. Придумайте логин (латиница) и пароль (от 4 символов) → **«Создать аккаунт»**.
4. Готово — вы в мессенджере. Второй аккаунт создаётся так же.

## Как общаться между компьютерами

На одном ПК (он же сервер):

1. Запустите «Искру». На экране входа будет надпись
   `Сервер запущен · 192.168.х.х:8787` — это адрес вашего сервера.
2. Если Windows спросит про доступ в сеть — разрешите для частных сетей.

На втором ПК:

1. Запустите «Искру», в поле **«Сервер»** впишите адрес первого ПК: `192.168.х.х:8787`.
2. Зарегистрируйте там новый аккаунт — и пишите.

> Сервер можно держать и отдельно: **`Сервер Искры.bat`** (запускает `Iskra.exe --server`
> без окна клиента). Данные лежат в `%APPDATA%\Iskra\server\db.json`.

## Удалённая работа

Из коробки «Искра» рассчитана на **локальную сеть**: клиент подключается к IP
сервера напрямую по TCP-порту 8787. Для связи между разными городами нужен один
из вариантов:

- **Tailscale или ZeroTier (рекомендуется).** Оба ПК входят в одну виртуальную
  сеть, в поле «Сервер» указывается адрес вида `100.x.y.z:8787`. Проброс портов
  на роутере не нужен, трафик шифруется самим VPN.
- **Сервер с публичным IP (VPS).** Запустите на нём `Iskra.exe --server`,
  откройте порт 8787 в брандмауэре. Если сервер домашний, проверьте, не выдаёт
  ли провайдер CGNAT — тогда проброс портов не поможет; при динамическом IP
  понадобится DDNS.
- **Туннель** (Cloudflare Tunnel, ngrok и подобные), если нет публичного IP.

> **Важно.** Сейчас протокол не шифруется: логин, пароль и сообщения передаются
> открытым JSON. Не публикуйте сервер в интернет «в лоб» — используйте VPN
> (тогда шифрование обеспечивает он) или сначала добавьте TLS.

## Данные

| Что | Где |
|---|---|
| Аккаунты и сообщения | `%APPDATA%\Iskra\server\db.json` |
| Настройки клиента (адрес сервера, логин, тема, язык, масштаб) | `%APPDATA%\Iskra\client.json` |

Можно переопределить папку данных переменной окружения `ISKRA_DATA`.

## Сборка из исходников

Нужен Rust (MSVC toolchain) и Visual Studio Build Tools.

```bat
Собрать.bat
```

или вручную:

```bat
cargo build --release
copy target\release\iskra.exe Iskra.exe
```

`Собрать.bat` поддерживает нестандартное расположение Rust: если `CARGO_HOME`
и `RUSTUP_HOME` не заданы, он использует `%USERPROFILE%\.cargo` и `%USERPROFILE%\.rustup`.
Готовый файл: `target\release\iskra.exe` (он же копируется в корень как `Iskra.exe`).

## Тесты

```bat
py -3 tests\protocol_test.py
```

Нужна уже собранная версия (см. выше). Тест поднимает **свой** сервер на случайном
свободном порту и пишет базу в `testdata\`, поэтому не трогает вашу реальную базу
в `%APPDATA%\Iskra`. Проверяются регистрация, вход, доставка сообщений, история,
прочтённость и сохранение данных между перезапусками.

## Устройство проекта

```
src/main.rs      — точка входа, авто-запуск сервера, режим --server
src/app.rs       — весь интерфейс: вход, список чатов, переписка, эмодзи, профиль, настройки
src/i18n.rs      — языки (RU/EN/DE/ES), все подписи и переводы ответов сервера
src/theme.rs     — палитра, темы, шрифты, аватарки, иконки, кнопки, плавные переходы
src/client.rs    — сетевой клиент с автопереподключением
src/server.rs    — сервер: TCP, аккаунты, сообщения, прочитанность, JSON-хранилище
src/protocol.rs  — общие типы и команды протокола
src/timefmt.rs   — локальное время и подписи дат на языке интерфейса
assets/          — RGBA-лист эмодзи и его превью (встраивается в exe)
tests/           — проверка протокола без GUI
tools/           — генератор листа эмодзи (нужен Pillow)
.github/workflows — сборка и тесты на GitHub Actions
```

Протокол — построчный JSON поверх TCP:

```json
{"t":"Login","d":{"username":"dima","password":"1234"}}
{"t":"SendMessage","d":{"to":2,"text":"Привет!"}}
```

## Ограничения

- Пароли передаются по сети без шифрования — используйте в доверенной локальной сети.
- Нет отправки файлов и групповых чатов (пока).
- Порт 8787 должен быть разрешён в брандмауэре для связи между ПК.
- Пока только Windows (зависимость `windows-sys`).
